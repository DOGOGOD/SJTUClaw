# Material Summary

**铁律：每个实质性结论都必须能追溯到已读取材料；未读取、被截断或互相冲突的内容必须如实标明。**

## 执行清单

- [ ] **1. 确定范围和用途 ⚠️ REQUIRED**
  - 提取材料路径、目标读者、摘要用途、详细程度、输出语言和交付方式。
  - 若用户给出目录或模糊范围，先清点文件，再排除明显无关、二进制或不可读取的内容。
  - 仅在范围过大或不同选择会显著改变结论时提问；其余缺项采用合理默认值并说明。

- [ ] **2. 建立材料清单 ⚠️ REQUIRED**
  - 记录每个候选文件的相对路径、类型、相关性和读取状态。
  - 优先读取标题、目录、摘要、正文结论与用户点名的章节，但不得把局部读取描述成全文覆盖。
  - 文件过大或工具返回截断内容时，在当前工具支持范围读取的前提下继续分段；否则在“范围说明”中列出未覆盖部分。
  - 不读取用户未授权范围之外的文件。

- [ ] **3. 逐份提取证据 ⚠️ REQUIRED**
  - 对每份材料提取：核心主题、关键观点、定义、数据/案例、前提限制和待确认项。
  - 保留可验证的来源标记，格式使用 `[来源：相对路径]`；只有真实可见时才追加章节、页码或行号。
  - 将自己的概括与材料原话区分开；直接引语保持简短并准确。

- [ ] **4. 跨材料综合 ⚠️ REQUIRED**
  - 按主题而不是按文件顺序组织内容。
  - 合并重复观点，同时保留各来源对同一问题的独特补充。
  - 分开呈现共识、分歧、证据不足和材料空白，不用“多数材料认为”替代实际来源。
  - 推论或建议必须单列并标注“基于材料的推断”，不得伪装成原文结论。

- [ ] **5. 选择输出形态**
  - **主题总结**：适合建立完整知识框架。
  - **复习提纲**：突出概念、关系、易错点和自测问题。
  - **项目概览**：突出目标、现状、决策、风险和待办。
  - **对照总结**：使用表格比较不同材料的观点、证据和限制。
  - 用户未指定时，根据其动词和用途选择最贴近的一种，并说明选择。

- [ ] **6. 交付或保存**
  - 用户未要求保存时，直接在对话中交付，不擅自创建文件。
  - 用户要求保存但未给路径时，使用基于主题的安全相对文件名，如 `主题-material-summary.md`。
  - 写入前避免意外覆盖现有文件；写入后仅在工具返回成功时报告保存完成。

- [ ] **7. 交付前检查 ⚠️ REQUIRED**
  - 清单中的每份材料是否标明“已读、部分读取、跳过或失败”？
  - 每个关键结论是否至少有一个真实来源？
  - 重复内容是否已合并，冲突内容是否仍然可见？
  - 是否删除了与用户用途无关的细节？
  - 是否把推断、建议和待确认项与材料事实分开？

## 默认输出骨架

```markdown
# 材料汇总：主题

## 范围说明
- 汇总目标：
- 已读取：
- 部分读取 / 跳过：
- 采用的假设：

## 核心结论
- 结论或共识。[来源：path/to/file]

## 主题一
- 关键观点与证据。[来源：path/to/file]
- 补充、限制或反例。[来源：path/to/other-file]

## 分歧与待确认
- 不同材料的冲突：
- 证据不足：

## 关键概念
- **术语**：定义或解释。[来源：path/to/file]

## 基于材料的推断（按需）
- 明确标注的推断或下一步建议。
```

## 禁止事项

- 不根据文件名、目录名或摘要猜测未读取的正文内容。
- 不遗漏“部分读取”和读取失败的范围限制。
- 不用无来源的通识知识悄悄补齐材料缺口。
- 不逐文件机械复述，也不为显得完整而保留重复内容。
- 不生成虚构的页码、章节、引语或来源路径。
