# Presentation Outline

**铁律：每一页只推进一个清晰观点；页面结构、证据和讲稿必须共同服务于同一条叙事主线。**

## 执行清单

- [ ] **1. 确认任务边界 ⚠️ REQUIRED**
  - 提取主题、展示目标、受众、总时长、语言、参考材料和交付方式。
  - 仅在缺少主题、展示目的等会显著改变结果的信息时提问。
  - 对非关键缺项采用合理默认值并在输出中说明：中文、普通课程受众、10 分钟、在对话中交付 Markdown 大纲。

- [ ] **2. 读取和整理材料 ⚠️ REQUIRED**
  - 先列出用户指定范围内的文件，再读取与主题相关的内容。
  - 从已读取材料中提取核心论点、数据、案例、图表线索和限制条件。
  - 为具体事实、数字、引语和非通识判断保留来源文件；不得为未读取内容虚构来源。
  - 材料互相冲突时保留差异，不擅自合并成单一结论。

- [ ] **3. 设计叙事主线 ⚠️ REQUIRED**
  - 先写一句“听众结束后应记住什么”，再安排页面。
  - 根据任务选择结构，不机械套用“背景—正文—总结”：
    - 解释型：问题 → 原理 → 案例 → 启示
    - 论证型：主张 → 证据 → 反方/限制 → 结论
    - 研究型：问题 → 方法 → 发现 → 局限 → 意义
    - 项目型：目标 → 方案 → 进展/结果 → 风险 → 下一步
  - 删除不能推进主线的页面；短展示不强制添加目录页或独立 Q&A 页。

- [ ] **4. 分配页面和时间 ⚠️ REQUIRED**
  - 先扣除用户明确要求的提问时间，再分配讲述时间。
  - 以每页约 45–90 秒为起点，根据内容密度调整；开场和收束应更短。
  - 为每页标注预计时长，并确认所有页面时长之和不超过总时长。

- [ ] **5. 生成逐页大纲 ⚠️ REQUIRED**
  - 使用能表达结论的标题，避免只有“背景”“分析”“案例”等标签式标题。
  - 每页提供：
    - **页面目的**：该页要让听众理解或相信什么
    - **屏幕内容**：2–4 个短要点，只保留可扫读信息
    - **视觉建议**：图表、流程、对比、时间线或关键数字；无必要时写“无需额外视觉”
    - **讲者备注**：口头展开内容，不复制屏幕文字
    - **过渡语**：自然引出下一页；末页改为收束句
    - **来源**：仅列本页实际使用的材料路径或已核验来源
    - **预计时长**

- [ ] **6. 交付或保存**
  - 用户未要求保存时，直接在对话中交付，不擅自创建文件。
  - 用户要求保存但未给路径时，使用基于主题的安全相对文件名，如 `主题-presentation-outline.md`。
  - 写入前避免意外覆盖现有文件；写入后仅在工具返回成功时报告保存完成。

- [ ] **7. 交付前检查 ⚠️ REQUIRED**
  - 标题串联起来能否独立讲清故事？
  - 每页是否只有一个中心观点，且要点不超过 4 个？
  - 所有数字、引语和关键事实是否有真实来源？
  - 讲者备注是否补充而非复述页面？
  - 总计时是否满足限制，开场与结尾是否留有余量？
  - 是否明确说明了采用的默认假设和未核验内容？

## 输出骨架

```markdown
# 展示方案：主题

## 基本信息
- 目标：
- 受众：
- 总时长：
- 核心信息：
- 采用的假设：

## 叙事主线
一句话说明各部分如何推进到最终结论。

## 第 1 页｜结论式标题（预计 0:40）
- 页面目的：
- 屏幕内容：
- 视觉建议：
- 讲者备注：
- 过渡语：
- 来源：

## 时间核对
- 讲述：X:XX
- 提问：X:XX
- 合计：X:XX
```

## 禁止事项

- 不为凑页数添加空洞目录、重复总结或装饰性页面。
- 不把长段落、完整讲稿或未经筛选的材料堆到屏幕上。
- 不编造数据、图表、引语、页码或参考来源。
- 不声称已生成 `.pptx`，除非确实使用相应工具创建并验证了文件。
